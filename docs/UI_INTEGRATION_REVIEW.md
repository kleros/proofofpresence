## Binding rules

- Carry stable `event.id` through routes, imports, async requests, transaction records and reviews. Slug/title are presentation. Include environment/server instance, chain, contract/version and wallet in any persisted transaction context. Discard unsubmitted reviews on event/account/network/source changes; retain submitted hashes under their original context.
- Use the server's `permissions` and current contract owner for presentation, then call the existing server draft/verification path. A role selector, disabled button, content editor, Supabase login or pasted wallet is not financial authority. The local demo picker remains explicitly simulated authentication; EOA signature login proves wallet control, not declared email ownership.
- Keep admission, deposit receipt, contract registration, personal history, staff observation and on-chain attendance separate. Free guests never enter the deposited pool. Personal “attended,” booth/merch and marketing records do not enter attendance plans.
- Preserve v7 native ETH and V1 resolver behavior. `Finalized` means ordinary payouts ran; matched cases, held shares and owed credits may remain. Do not replace held-share settlement with a blanket freeze. Ruling 0 excludes attendance and splits remaining challenge funds, not principal as a consolation payout.
- Use chain `now` and contract deadlines for financial availability. Public schedule is ISO + IANA timezone; financial deadlines are Unix seconds; draft `expiresAt` is wall-clock milliseconds. `claimDeadline` is the attendance-posting/no-list recovery deadline, not a universal cutoff for claims or Court cases.
- Display exact `valueWei` and actual `transaction.to` before signing; appeals/evidence may target the resolver rather than the event contract. Evidence/appeals use resolver local IDs; Court progression/delivery uses arbitrator IDs. A final vote, final resolver result, settlement receipt and successful transfer are distinct facts.
- Preserve private/draft route guards and authorized participant recovery access. An association UUID/URL does not grant Supabase content/material access. Continue linking retained content/Q&A/media and booth modules without copying their protected data into public root projections.

## Existing data the redesign can consume

| UI purpose | Actual source / contract | Important interpretation |
|---|---|---|
| Directory/context | `GET /api/bootstrap`: `events`, `session`, `mode`, `chain`, `now` | Anonymous public browsing exists. This is the local finance catalogue, not the full retained content directory. |
| Deployment identity | `detail.event`: `id`, `chainId`, `contract`, `deploymentBlock`, `contractVersion`, `abiVersion`, `policyURI`, `templateHash`, deposit/schedule/deadlines | Address/config comes from the trusted adapter; query parameters cannot supply a replacement contract. |
| Editorial/registration/finance | `visibility`, `editorialStatus`, `registrationStatus`; `detail.state.phase` | These are independent. Use `state.phase` for consequential detail actions. |
| Participant identity/admission | Own authorized `detail.participants[]`: `id`, `eventId`, declared contact, verified wallet/source, `admission` | Owner/staff see necessary event rows; attendees see their own row. |
| Deposit evidence | `participant.deposit`: receipt hash/log/block/chain/contract/amount, `verified` | This is receipt evidence, not admission. A historical verified pointer does not by itself describe remaining principal after a later return. |
| Registration/attendance | `participant.registered`, `attended`; `state.stakers`, `activeStakers`, `stakerHistory`, `attendees` | `registered` and `stakers` include paid status. Use `activeStakers` for a new attendance proposal; historical membership is not current eligibility. |
| Staff observation | `detail.attendance[]`: participant/event/source/reviewer/time/nonce or batch/hash | Observation differs from final financial attendance. Staff writes require authenticated event scope and replay-safe nonce. |
| Personal history | `detail.personal`: `{attended,source:'self-reported'}` | Not the retained content app's complete saved/going/notes model. |
| Reconciliation ledger | Privileged `detail.deposits`, `unmatched`: received/returned/allocated/unallocated wei, source transactions and identity linkage | Unallocated is not an automatic refund entitlement. Owner review and contract reserve checks still apply. |
| Obligations | `state.balanceWei`, `reservedWei`, `spareWei`, `heldBackWei`, `owedTotalWei`, `challengeEscrowWei`, `poolWei`, `payoutShareWei` | Held shares and owed credits are components of total reserved; do not add them to reserved again. The pool is a nominal registered pool, not current balance. |
| Case state | `state.cases[]`: challenge state, `matched`, resolution outcome, matcher, matching deadline/deposit, held share, final result, publication, appeal costs/periods | Use `matched` to distinguish Court cases. The core fix now returns null IDs and `not-applicable` publication for unmatched acceptance. |
| Reviewed transactions | `POST /drafts`; `/validate`, `/execute`, `/confirm`; `detail.transactions[]` | Exact simulation/receipt path exists. Transactions carry hash/status/action/wallet/event/block; they are not an amount ledger or complete history index. |
| Evidence publication | `/cases/:wallet/publish`, `/local-upload`, local gateway | Status `local-only` is not public IPFS availability. A computed CID is not evidence of publication. |

`src/domain.ts` currently omits runtime `contentEventId` and most projection interfaces. `docs/API.md` also omits some existing response fields (`deposits`, `unmatched`, `activeStakers`, `stakerHistory`). Use the actual adapters above and reconcile these descriptions during integration instead of inventing fallback values.

## Gaps and safe integration choices

| Priority | Gap in current core contract | Required treatment |
|---|---|---|
| P1 | Walletless free participation is requested by the design, but `POST /participants` requires an authenticated wallet. | Use a configured external free-request/Luma route with an honest label, or add a separate nonfinancial free-request model/API. Do not make a fake wallet/session prerequisite disappear only cosmetically. Do not claim native walletless registration is complete today. |
| P1 | Initial core had no authoritative sent/transferred total. `transactions` omit amounts; deposit ledger is incoming/returns, not settlement transfers. | Follow-up `src/payments.mjs` now supplies `projectPayments(chain,record,{blockTag})` for core integration. `attendancePaidWei`/`directAttendancePaidWei` are direct successful attendance payments; principal/spare returns, failed-credit creation and unattributed owed claims remain separate. Its total is explicitly not complete native-transfer history. Never derive sent as `pool - balance`, add failed credits as payments, or label all claims attendance rewards. |
| P1 | `POST /imports` validates **and commits** an atomic off-chain batch immediately; it returns `rows:number`, `errors:[]` on success, not a reconciliation row array. | A client-only source preview is acceptable if labeled provisional, preserves every source row/byte and then submits the complete original batch through the server. A real server preview/commit API is needed if the UI promises authoritative exclusions or a persisted review plan. Make “Apply reviewed import” separate from later financial transaction review. |
| P1, fixed in core | Initial `state>=2` projection/dispatch mistook resolved unmatched/owner-corrected challenges for matched case 0. | Core now exposes `matched`, nulls unmatched IDs/results and rejects resolver/publication operations with `NOT_MATCHED_CASE`. The redesign must consume that distinction, hide resolver actions for unmatched acceptance and avoid reintroducing the old enum-only check. Exact correction-versus-expiry history still needs event provenance if shown. |
| P1 | Browser-wallet submission hashes are not durably recorded before confirmation. Existing frontend invalidation can discard the draft after a wallet sends and only show the hash in an error. | Add a namespaced submitted-transaction journal or a validated pending-hash server operation. Bind callbacks to captured original event/wallet, not the currently selected route; recovery must not offer a second deposit while the first receipt is unresolved. |
| P2 | No normalized action-capability/blocked-reason projection; raw participant status and principal disposition are incomplete. | Keep server simulation as final authority. Add a shared adapter for one eligible next action and reason; do not duplicate financial algorithms across components. Explicitly handle refunded receipt → allowed fresh deposit, paid vs active staker and unavailable reads. |
| P2 | Appeal projection has current ruling/period/costs but no contribution/funded-side/reward ledger. | Preserve direct contributor-to-resolver actions and retained advanced tools. Add resolver reads for funded/contributed/withdrawable values before claiming appeal-money totals. Do not infer them from the event contract balance. |
| P2 | Root lacks full content search/calendar/archive/My-events data and native Supabase session bridge. | Retain links/routes and privacy in the existing content module. A compact redesigned shell is not permission to remove those capabilities or manufacture recordings/private data. |

The UI worktree's inspected `public/reconciliation.js` already follows a useful provisional-preview approach: it does not mutate projections, labels new receipt references “Server verification required,” keeps excluded rows visible and hard-blocks known identity/chain/contract conflicts. Its rules must remain aligned with the backend; tests must detect drift. Its `person.registered` check should not be mistaken for `activeStakers` in an attendance proposal.

## Required merge and acceptance checks

1. **Merge boundary:** incoming `src/server.mjs` changes were limited at inspection to static asset MIME/allowlist, binary-safe asset serving and exposing server `instanceId`. Apply those hunks onto the current core, preserving newer auth/Host/origin/private/draft/transaction guards. Do not copy the snapshot server wholesale. Re-run route/privacy tests after the merge.
2. **Two events / stale async:** delay Event A detail/import/draft responses, switch to B and switch wallet/network; no A data or signing authority may replace B. Unsubmitted plans clear. A submitted hash remains discoverable under A after navigation/reload.
3. **Participant state matrix:** disconnected, wrong network, free path, pending receipt, verified receipt/admission pending, approved/unregistered, registered, staff-observed, omitted, unmatched, matched, appeal open, resolver-final/unsettled, paid, owed, cancelled and no-list recovery. Test read failure separately from user rejection, confirmed revert and pending receipt.
4. **Reconciliation:** raw unknown origin requires recorded review; known event/contract/chain/Luma/participant mismatch stays blocked; duplicate receipts and stale plans cannot be acknowledged through. UI preview and server parsing agree on quoted CSV, BOM, normalized duplicate headers and row limits. Check the original bytes sent and actual committed batch, not only a green preview.
5. **Authority/privacy:** owner A, staff A, participant and outsider exercise both events through direct API calls as well as the UI. Staff can observe but cannot admit/register/pay. Private/draft content remains hidden while authorized participants keep recovery access. Content/editor identity does not imply contract ownership.
6. **Money/cases:** repeat existing real-v7 integration checks through the redesigned controls: normal payouts with open held shares; both late winner/loser orders; ruling 0; Event B unaffected; failed-transfer owed claim to alternate recipient; cancellation/no-list limits. An unmatched resolved challenge must never acquire another resolver case's IDs/result/actions.
7. **Review/signing:** event, network, version, full contract, actual transaction recipient, exact wei, signer, policy, effects and freshness remain reviewable on mobile. Verify direct resolver appeal attribution and local-ID vs arbitrator-ID dispatch. No static prototype success states replace receipts.
8. **Desktop/mobile/accessibility:** inspect real browser output at 1440×900 and 400×800, enlarged text, overflow/address wrapping, visible labels/focus, keyboard tabs, dialog focus containment/restoration, Escape, reduced motion and announced async errors. Required primary controls meet the chosen 44px design target. Keep all supplied font licenses and unchanged logo assets.

Preserve the existing core build/typecheck, Node integration and legacy financial checks. Run the UI-specific parser/browser tests on the integrated root, not only the isolated snapshot. Record exact commands/results and inspect screenshots; the package's 49 DOM checks and static PDF are design evidence, not proof of this integrated application.
